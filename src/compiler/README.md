# The Faz compiler

The compiler is written in Faz and emits LLVM IR directly. A narrow typed C-API bridge loads LLVM in-process to verify, optimize, and emit native objects; Faz then invokes the platform linker. Normal builds never invoke Clang. The runtime is embedded, so the installed compiler does not need this source tree.

After the initial build, from the repository root:

```sh
build/faz build-self
build/faz build src/compiler/main.fz --legacy-language -o build/faz-next
build/faz-next run examples/hello.fz
```

Start with `main.fz` for the CLI, or follow the compilation stages:

1. `lexer.fz` produces tokens and source locations.
2. `parser.fz` builds the tree defined in `syntax.fz`.
3. `modules.fz` resolves file-relative imports and qualifies names.
4. `semantic.fz` checks types, assignment, matches, and control flow.
5. `llvm_emitter.fz` emits instructions, managed reference slots, and task adapters.

`runtime_source.fz` is generated by `faz embed-runtime src -o src/compiler/runtime_source.fz`. It bundles the runtime for standalone compiler distribution; edit the sources in `src/runtime/` and `src/std/` instead.

See [native toolchain and distribution details](../../docs/native-toolchain.md), or the [repository README](../../README.md#faz-makes-faz) for bootstrap seeds and maintenance commands, and the [examples](../../examples) for supported syntax.

## Core-language transition

Normal `build`, `run`, `check`, and `emit-llvm` commands enforce the new core
language rules. The compiler implementation and historical regression corpus
have **not yet been migrated** to those ownership rules. They are compiled with
an explicit `--legacy-language` compatibility flag; this is not selected by a
source filename, directory, or environment variable. Do not use this flag to
claim that a program conforms to the new language specification.

`build-self`, `test`, `verify`, and `refresh-seed` opt into that compatibility
mode for the compiler and old tests. Bootstrap capability detection permits the
old checked-in seed to produce the first updated compiler; every updated stage
uses the explicit flag. Core-language tests invoke the compiler without it.
Installed compilers retain the new default rules.
